# dejavu

見たものを、名前が付く前から覚えておくための実験場。

顔認識ではない。顔認識は「これは誰か」に答える装置だが、ここで作りたいのは
**「これ、見覚えがある」に答えられること**のほうで、名前はその後から乗る。

## なぜ

Claude Code から見える視覚は、`see` を呼んだ瞬間にしか存在しない。呼ばなければ
何も見ていないし、見たものは名前を付けた分しか残らない。

[heishio/embodied-claude-rem](https://github.com/heishio/embodied-claude-rem) の
vision-server は、そこに無いものを持っていた。呼ばれていない間も像が溜まり、
名前が付く前のまま重心で照合できる。あれを読んで、自分で組み直したのがこれ。

コードは持ってきていない。読んで理解した概念を、別の設計で書いた。

## 設計

### 3つのチャンネルを分けて持つ

| kind | 中身 | 効く場面 | 死ぬ場面 |
|---|---|---|---|
| `scene` | 人物マスクの外側パッチの平均 | 人が写っていなくても場所が分かる | 模様替え・カメラの移動 |
| `person` | 人物マスクの内側パッチの平均（服を含む） | 顔が見えなくても追える | 着替えると死ぬ |
| `face` | 顔クロップのパッチ平均 | 日をまたいでも生きる | 顔が撮れないと使えない |

**分けて持つことが要点。**混ぜて1本にすると、「同じ人だ」と言われたときに
顔で当てたのか服の色で当てたのかが分からなくなる。根拠が言えない再認は使えない。

`person` は短期の追跡、`face` は長期の同定と、担当する時間スケールが違う。

### 本家の memory.db には書かない

記憶本体は [lifemate-ai/embodied-claude](https://github.com/lifemate-ai/embodied-claude)
の memory-mcp が持っている。そちらのスキーマには一切触らず、`vision.db` を別ファイルで持つ。
参照が要るときは読み取り専用で ATTACH する。

```python
ATTACH DATABASE 'file:~/.claude/memories/memory.db?mode=ro' AS mem
SELECT o.label, m.content FROM observations o JOIN mem.memories m ON m.id = o.memory_id
```

`mode=ro` なので、書こうとすると `attempt to write a readonly database` で弾かれる。
約束ではなく構造で守る。

> memory.db は `journal_mode=wal`。WAL では attach をまたぐ書き込みの原子性が
> 保証されないため、そもそも跨いで書かない設計にしてある。

### 返すのは「強さ」で、名前は候補

**判定しない。**「これは誰か」を断定せず、「見覚えがどれくらいあるか」を返す。

```
face: 強く見覚えがある。候補は「人物A」・3回この群れで見ている  〈別人ラインとの差 +0.083 / 鋭さ +0.142〉
face: 見た気がする。名前は知らない（fac-870561a7acca）        〈別人ラインとの差 -0.034 / 鋭さ +0.064〉
face: 初めて
```

そうする理由は、実測から出ている。**盲検で、システムは間違った人を指しながら
「自信がない」ことは正しく伝えていた。**名前だけを返す設計なら、受け取った側は
誤った名前を復唱していた。**確信度は答えより先に届く。**

受け取るのは Claude Code 自身なので、弱い信号は弱いまま渡ってくれたほうが使える。
他の材料（いま部屋にいるはずの人、直前の発話、時刻）と重みをつけて合わせられる。
確信のある誤答より、確信のない正答のほうが役に立つ。

### 段階は5つ。4つは階段で、1つは階段の外にある

| 段階 | 意味 | 条件 |
|---|---|---|
| 強く見覚えがある | よく見かける人物・いつもの人物 | 別人ラインとの差 ≥ +0.05 かつ 群れが3枚以上 |
| 見覚えがある | たぶん一度は見たことがある | 別人ラインとの差 ≥ +0.05 |
| 見た気がする | 見たことあるかも？ | 別人ラインとの差 ≥ −0.035 |
| 初めて | 何も引っかからない | それ以外 |
| **むしろ見た気がする** | **既視感** | 別人ラインとの差 < −0.035 **かつ 鋭さ ≥ +0.07** |

**「別人ライン」は「別人でもこれくらいは似る」線**——ラベルの違う群れ同士の
**最大**類似度。「これ以上似ていなければ、別人同士でもありうる」という高さのこと。
DINOv2 のコサイン類似度は絶対値が環境をまたがないので、生の数字ではなく
このラインとの差で見る。**鋭さ**は1位と2位の差。

最後の段階が階段の外にあるのは、**既視感の本来の意味がそこにあるから**。
実際には初めてなのに見た気がする錯覚——強度は別人ラインを下回っているのに、
鋭さだけが立っている状態。実測では、DB に居ない人物に対してこれが2件出た。
**どちらも指す先は誤り。**錯覚であることまで再現している。

### 過分割は自動では畳めない

しきい値を高くして過分割に倒すのは、後から統合できるからだ——と考えていたが、
実測すると**そうはならなかった**。群れの重心同士の距離で統合候補を並べると:

```
0.8559  人物B(1,4) + 人物A_4      ← 別人。しかも1位
0.8388  人物B(1,4) + 人物B_3      ← 正しい統合
0.7716  人物A(1,3) + 人物A_4      ← 正しい統合
```

正しい統合より上に誤った統合が来る。距離順に自動で畳むと、しきい値を高く保って
避けていたはずの混在を、統合の段階で作り込むことになる。

**統合には外からの信号が要る。**人が両方の群れに同じ名前を付けたとか、同一セッションで
連続して観測されたとか。`clusters.label` は飾りではなく、統合を許可する権限を持っている。

> この節の実測は、しきい値を高く（0.87）置いて混在ゼロを守っていた時期のもの。
> 現在は取りこぼしゼロを優先して 0.80 まで下げ、**混在をある程度許している**。
> 統合の知見自体は生きているが、「高いしきい値で過分割に倒す」前提は採っていない。

### 時間を足すと、途中まで自動化できる

外からの信号のうち、機械で取れるものが1つある。**人は瞬間移動しない。**
連続して観測された2つの群れなら、同じ人である公算が高い。

`suggest_merges(kind, sim, max_gap_seconds=)` は、群れ同士のいちばん近いメンバーが
その秒数以内に観測された組だけを残す。face の候補13組に対して:

| 時間の門 | 残る候補 | うち誤り |
|---|---|---|
| なし | 13 組 | **1位が誤り** |
| **60 秒** | **1 組** | **0** |
| 120 秒 | 3 組 | 2 |
| 300 秒 | 5 組 | 4 |

距離だけでは1位だった誤った統合が、時間で落ちる。`automerge.py` はこの門をくぐった
候補だけを畳む。しきい値 0.87 で測ったときは **face 11→7 群れ・混在ゼロ**（6人に対し
過分割1件）まで畳めた。**外からの信号を足せば安全に畳める。距離だけでは畳めない。**

現在のしきい値 0.80 では最初から群れが少ないので、統合の出番は減っている。
過分割を高いしきい値で作ってから畳む道も残ってはいるが、既視感としては
**最初から取りこぼさないほう**を採った。

> **この 60 秒という値は信用してはいけない。**手元の素材の時刻はダウンロード時刻であって
> 撮影時刻ではないし、同一人物が 10 秒差・別人が 64 秒差という、マージン 4 秒の境界を
> 通っているだけ。方向（外からの信号を足せば自動化に近づく）は支持されたが、値は
> 環境ごとに較正が要る。

そして**時間でも救えないものは残る**。手元では face の1件が、同一人物なのに
37 分離れているため門をくぐれない。距離で畳もうとすると別人のほうが近い。
**この1件は人が名前を付けて教えるしかない。**

## 実測（2026-08-20、16枚7人）

指標は「混在ゼロ」ではなく「**見た人を見たと言えた率**」。既視感の致命的な失敗は
「別人を同一と判定」ではなく「**見た人を初めてと言う**」ほうなので。

2種類の抜き方で測る（`evaluate.py`）。

| | 中身 | 結果 |
|---|---|---|
| leave-one-image-out | その人の他の写真は DB にある | **「初めて」ゼロ / 16枚**（取りこぼしなし） |
| leave-one-person-out | その人の写真は DB に1枚も無い | 「初めて」8 / 見た気がする4 / 見覚えがある2 / **むしろ見た気がする2** |

- 見た人 16枚の内訳：強く見覚えがある 2 / 見覚えがある 8 / 見た気がする 6
- 1位の候補が正解と一致：**15/16**（外れた1枚は強度だけ正しく、候補が別人）

### 取りこぼしゼロには代償がある

しきい値 0.80 では、**人物A と 人物B が同じ顔の群れに入る**（9群れ / 7人、混在1件）。
0.87 まで上げれば混在は消えるが、そのとき見た人の強度が −0.098 まで落ち、
**「初めて」と言い始める**。両立しない。取りこぼしを避けるほうを採った。

混在の**自動検出は成立しなかった**。群れのまとまり（メンバーと重心の最小類似度）は
枚数と強く相関するので、12枚の正常な群れが「幅が広い」と判定され、3枚の混在した
群れは通ってしまう。そもそも混在の自動検出は「混在を避ける」のと同じ問題で、
それが簡単ならクラスタリング自体がそうしている。

**防波堤は人の目に置いた。**`set_label()` は名前を付けたあと群れの中身を返す。

```
名前を付けた: fac-529f99934a0d → 人物A
  人物A_4.webp
  人物B_4.webp   ← 人が見れば気づく
  人物B_1.webp
```

### 他の実測

| 項目 | 結果 |
|---|---|
| `scene` の新奇性検出 | カメラごとに z のマージン +1.9 〜 +2.0 で分離（`novelty.py`） |
| 顔検出なしのパッチ検索 | 16枚中15枚正解 |
| 顔検出の誤検出フィルタ | 本物17枚は人物マスクと 0.675〜1.000 重なる。誤検出は 0.000 |
| 顔クロップの余白 | 0.10〜0.35 が最良。0 でも分離する（服の色で当てているのではない） |
| CLS vs パッチ平均 | **パッチ平均のほうが頑健**。余白を広げたとき CLS は崩れる |

### しきい値は到着順で変わる

貪欲な逐次クラスタリングは、観測が来る順番で結果が変わる。同じしきい値でも、
ファイル名順なら混在ゼロ、時刻順なら混在1件、ということが起きる。

| face のしきい値 | 時刻順 | ファイル名順 | 無作為20通りの混在 |
|---|---|---|---|
| 0.80 | 1 | 0 | 最小0 / 最大1 / 平均0.65 |
| 0.86 | 0 | 0 | 最小0 / 最大1 / 平均0.25 |
| **0.87** | **0** | **0** | **すべて0** |

**1つの順序だけで較正すると、安全に見えて安全でない値が出る。**
`calibrate.py` は時刻順・ファイル名順に加えて 30 通りの無作為な順序で検証する。
実運用では観測は時刻順に届くので、`ingest.py` も時刻順で処理する。

> ここで 0.87 が推奨として出るのは、`calibrate.py` の判定が「混在ゼロ」だからで、
> **顔認証の物差し**。既視感としては 0.80 を採っている（混在を許して取りこぼしを避ける）。
> 順序で結果が変わるという事実自体は、どちらの物差しでも有効。

### 分かっている限界

- **絶対しきい値は環境をまたがない。** DINOv2 のコサイン類似度は別人ラインが高く、
  この素材では全部 0.45〜0.75 に集中する。しきい値は環境ごとに較正が要る。
- **顔検出器は横顔で落ちる。** `blaze_face_short_range` は正面向き用。
  16枚中2枚で検出できなかった。ただし**2枚とも `person` チャンネルが拾った**
  （1枚はクラスタリングで、1枚は時間の門による統合で）。顔が撮れないことは
  致命傷にならない、という設計上の狙いは成立している。
- **似た属性の別人は混ざりやすい。** 黒髪・同年代・同性の2人が一貫して最接近ペアになる。
  これは DINOv2 が汎用モデルだからではない。顔認識のために学習された FaceNet
  （InceptionResnetV1 / vggface2）を同じ顔クロップで測ると、平均の分離は大きく上回る
  （同一 0.75 / 別人 0.32、差 0.43。DINOv2 は 0.84 / 0.66、差 0.18）のに、
  **最悪ケースの重なりは −0.1603 対 −0.1499 でむしろ悪い**。混在ゼロを要求すると
  しきい値は最悪ケースで決まるので、群れ数は 8 対 11 にとどまり、質的な差にならない。
  混同する相手が入れ替わるだけだった（DINOv2 は 人物A×人物B、FaceNet は
  人物B×人物C が最接近）。
  ★**ただしこの結論は「混在ゼロ」という物差しの産物**だった。既視感の物差しなら、
  平均の分離が2倍以上あることそのものが価値になる。乗り換えない理由は
  「効かないから」ではなく、下記のライセンスのほう。
- **顔専用モデルへの乗り換えは、そもそもライセンスが難しい。** 顔認識モデルの重みは
  ほぼ全て研究用データセット（MS1M / WebFace / VGGFace2 / CASIA）で学習されており、
  コードが MIT でも重みは非商用研究限定、あるいはライセンス未記載であることが多い。
  InsightFace は「コードは MIT、学習データとそれで学習したモデルは非商用研究用途のみ」と
  明記している。DINOv2 が例外的に安全なのは、Meta が自前の LVD-142M で学習し
  **重みごと Apache-2.0** で出しているため。
- **人物の存在判定は、セグメンタの `person_ratio` でも当てにならない。**
  ベクトル類似度で門番を作るより素直に見えるが、**人が写っていない25枚のうち11枚で
  `person` ベクトルが生成された**。最悪は白い布団のベッドで人物率 **0.708**——
  布団の膨らみを横たわった人と誤認する。自室のカメラはベッドを常時見るので、
  そこを人として検出し続けることになる。0.15 程度のしきい値で大半は落とせるが、
  この種の例は残る。

## MCP サーバーとして使う

**stdio 型。ポートを開かず、常駐プロセスも持たない。**Claude Code がセッションごとに
子プロセスとして起動し、終われば落ちる。`memory-mcp` が HTTP recall のために 18900 番を
常駐させるのとは違い、こちらはポートを持たないので、常駐プロセスの管理が要らない。

道具は4つ。

| 道具 | すること |
|---|---|
| `observe(image_path, camera?)` | 見て記録し、見覚えの強さを返す |
| `recall(image_path)` | **記録せず**、見覚えだけ返す |
| `name(cluster_id, label)` | 群れに名前を与え、**何に付けたかを返す** |
| `views(camera, image_path?)` | そのカメラの「いつもの眺め」と「いつもと違うか」 |

登録手順は [docs/mcp-registration.md](docs/mcp-registration.md)。

## 構成

```
src/dejavu_mcp/
  server.py    MCP サーバー（stdio）。道具4つ
  vision.py    モデル層。1枚から scene / person / face を作る
  store.py     保存層。vision.db への読み書き・逐次クラスタリング・既視感の判定
  schema.sql   vision.db の定義。命名は本家 memory-mcp の流儀に合わせてある

tools/         CLI。実運用の下ごしらえと較正
  ingest.py    images/ を投入して群れを作る
  recall.py    「この画像、見覚えある？」に答える
  calibrate.py この環境でのしきい値を素材から出す（移植のたびに必要）
  evaluate.py  既視感としての性能を測る（見た人を見たと言えた率）
  automerge.py 時間の門をくぐった統合候補だけを畳む
  novelty.py   scene を「いつもと違うか」の検出器として測る

experiments/   測って捨てた検証。設計判断の履歴として残してある
  embed_faces.py      顔クロップ同士の類似度マージンを測る
  patch_search.py     顔検出器を使わずにパッチ検索で当てる
  segmented_search.py 背景グレー塗り・輝度正規化の効果を測る
  stage2_search.py    人物領域でパッチを絞る効果を測る
  presence_gate.py    「人がいる／いない」の門番が作れるか測る
  cluster.py          しきい値を振ってクラスタリングの質を測る
```

`images/` と `models/` と `vision.db` は追跡していない。顔写真は個人情報なので
リポジトリには入れない。モデルは公開されているものを取得する。

```powershell
# 顔検出（Apache-2.0）
curl -o models/blaze_face_short_range.tflite https://storage.googleapis.com/mediapipe-models/face_detector/blaze_face_short_range/float16/latest/blaze_face_short_range.tflite
# 人物セグメンテーション（Apache-2.0）
curl -o models/selfie_segmenter.tflite https://storage.googleapis.com/mediapipe-models/image_segmenter/selfie_segmenter/float16/latest/selfie_segmenter.tflite
```

DINOv2（`facebook/dinov2-with-registers-base`, Apache-2.0）は初回実行時に
HuggingFace から自動で取得される。

### 依存

```powershell
uv venv --python 3.12
uv pip install torch torchvision --index-url https://download.pytorch.org/whl/cu124
uv pip install transformers mediapipe pillow numpy opencv-python
```

CUDA は必須ではない。`.cuda()` はすべて `torch.cuda.is_available()` で守ってあるので
CPU でも動く。実測は RTX 500 Ada (4GB) で、DINOv2 の推論時 VRAM 使用は約 340MB。

> `transformers` の `AutoImageProcessor` は `torchvision` を要求する。
> `torch` だけ入れると ImportError になる。
